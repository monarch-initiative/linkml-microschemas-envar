    Why it matters & mappings

    A hash verifies a file you already have; only a locator lets you find it.

    Input File SHA-256 Hashrecommended

    input_file_sha256 · range String · cardinality 0..1

    A SHA-256 hash is a fingerprint of a file — if even one byte changes, the fingerprint changes completely. Comparing fingerprints proves two files are exactly the same without inspecting their contents.

    SHA256 of this input file (CSV / parquet).

    Example

    9f8e7d6c5b4a...

    Evidence: 1 supporting, 5 not supporting
    OMOP / GAIAverifiedoutput, partial match
    output checksum = TBD
    where gaiaCatalog ETL file of global_pm25_concentration_1998_2016
    The ETL file of a catalogue entry has a `checksum` field next to the source URL and file name, and the DCAT record has `spdx:checksum`. Missing: in the public example it is not filled (TBD), and neither the algorithm nor the file it belongs to is stated.

    C-HERunverified, to be reviewedabsent (old verdict)

    CODATA Essential Variables / DDI-CDIunverified, to be reviewedout of layer (old verdict)
    File checksums are instance-layer; out of scope for CODATA.
    Why it matters & mappings

    The input hash lets anyone verify they are re-running on byte-identical inputs; without it, a "reproduction" may quietly use different data, and disagreements can no longer be traced to inputs versus code.

    See also: https://doi.org/10.6028/NIST.FIPS.180-4

    Input Row Countrecommended

    input_row_count · range Integer · cardinality 0..1

    Just the number of lines of data that went in. If you expected 3 addresses and the count says 2, something was lost before the tool ever ran.

    Number of rows in this input file.

    Example

    3 — one row per cohort address

    Evidence: 0 supporting, 6 not supporting
    CHELunverifiedshould record it, does not: not recorded
    No row count of an input is published. Nothing close was found in Documentation.md, README.md or the data folder.
    OMOP / GAIAunverifiedshould record it, does not: not recorded
    No row count of the loaded locations or source tables is stored. Closest: `working.location_statistics()`, which prints summary counts on request.

    No row count of the input is written. Nothing close was found in the READMEs, the code or the example outputs.
    amadeusunverified, to be reviewedabsent (old verdict)
    No native Amadeus file records an input row count.
    C-HERunverified, to be reviewedabsent (old verdict)
    C-HER records no per-run input row count.
    CODATA Essential Variables / DDI-CDIunverified, to be reviewedout of layer (old verdict)
    Row counts are instance-layer; out of scope for CODATA.
    Why it matters & mappings

    The row count is a coarse but instant integrity check — a truncated or partially delivered input shows up immediately as the wrong count. It also anchors the input side of input/output cardinality checks.
